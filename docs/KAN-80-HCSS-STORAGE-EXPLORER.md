# KAN-80 — Primary HC Storage Service UI

## Goal and contract

**HomeCloudUI → existing Backend control WebSocket → HC Storage Service on its storage node.**

HomeCloudUI does not open a filesystem directly and never connects to HC SS / Media Gateway by guessed endpoints. The existing Tauri commands `homecloud_hcss_sources` and `homecloud_hcss_browse` reuse the per-Backend identified WS created for KAN-79.

- `storage.agent.status`: `agents[]`, `storage_node_id`, heartbeat-derived `online`, inventory `volumes[]`, published `roots[]`. The root inventory contains **root kind/id and permissions**, not the private host configuration paths.
- `storage.fs.list`: the Backend forwards `storage_node_id`, `root:{kind,id}`, root-relative `path`, and `limit=500`. HC SS resolves inside a locally allowlisted root, checks confinement and returns `items[]` (file/directory, name, root-relative path, size and modified time). File IDs are HCS1, generated by HC SS; they are not secrets or access credentials.
- No separate registry or file index is created in UI. Each selected Backend has a distinct agent registry and asynchronous responses are ignored after a selection change or unmount.

## Storage page UX

The default `Хранилища` tab is now **HC Storage Service**. It displays:
1. Backend and current control-connection state.
2. Agent nodes (including offline), last heartbeat and root count.
3. Mounted filesystem inventory, capacity and available bytes; physical block devices **not double-counted** as mounted filesystems.
4. Published HC SS root cards, each with online/list/read/write permissions. Selecting roots never changes their permissions.
5. Actual directory navigation, parent/breadcrumb links, per-directory name filter, file size/mtime and native `hc1.*` file IDs. Search is restricted to currently returned entries; it is **not** a recursive/global index.

Legacy Storage Manager compatibility was deliberately **removed** after on-device verification. The sole storage screen is HC SS, and the media tab no longer queries the old registered-file catalog. The old storage upload/download/registration IPC commands and obsolete dialog capability have been removed; there is no fallback to /ws/storage. The local media player and real HC SS → TV launcher remain unchanged.

## Explicit V1 limitations and safety

- **Read-only interface:** Backend/HC SS currently expose inventory, `fs.list` and `fs.stat`. There is **no HC SS upload/download/write/move/delete relay contract** yet. Do not route such actions through the unrelated old `storage.upload.prepare` or `storage.download.prepare` endpoints.
- No directory pagination. HC SS understands `cursor`, but `internal/wsserver/storage_agent.go` does not forward it. The screen displays at most the first 500 items and calls this limitation out when `next_cursor` is present. A next protocol PR should propagate and validate opaque root-scoped cursors with expiration.
- The Backend forwards control metadata only. Large bytes need a separate, authenticated, least-privileged data channel, with timeouts, quotas, resume/abort and symlink-safe root confinement.
- Published roots may differ from mounted volumes. A detected disk must never imply permission to read its files.
- No restart of TV, Backend, Gateway or HC SS is required for this UI-only PR. User-confirmed HC SS browse verification preceded removal of the legacy tab; the final cleaned release still requires installation verification.
